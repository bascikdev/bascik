Generative UI can mean three things. The model picks from a catalog you approved. The model emits a structured description that the app renders. The model writes raw code. @bascik/ai is the first kind, delivered as the second. The model writes component tags, and a renderer on the server draws only the tags in your catalog, as real HTML.

It is never the third kind. Model output is untrusted text. It is never run as code, and unknown tags are shown as text. Bascik ships plain HTML, with no client framework. The reader gets prose and finished components as one HTML document that grows. The browser needs no JavaScript for that core reply.

Chat is a complete chat interface. It covers the message box, thread, tool approval, memory, conversation search, attachments, and the server helpers behind them.

  • A composer and thread for stored messages.
  • Tool approval, memory, and conversation search.
  • Attachments and server helpers.

The model shows components from your catalog, a folder of ordinary Bascik components, rendered on the server as real HTML.

  • A folder of approved components.
  • A prompt built from each component file.
  • A renderer that keeps only catalog tags.

Voice gives a chat spoken conversations with a speech model. It shows word-by-word captions, lets the model show components while it talks, and can fill in a form the reader answers aloud.

  • Captions and read aloud for replies.
  • Spoken calls with Gemini Live or Azure Voice Live.
  • Forms that can be pressed or answered aloud.
    The reader sends a message through a form or a voice call. The server reads the catalog and sends the prompt and messages to a model. The model returns prose and catalog tags, and the renderer holds each tag until it is complete. Bascik renders approved tags as scoped HTML and sends the growing page to the browser.
  • It does not run model output as code.
  • It does not turn unknown tags into elements.
  • It does not work as a static build, because it needs a server that runs stream scripts.
  • It is not stable yet, because it is an experimental 0.x prototype.
  • It does not offer browser-only tools in voice calls.
  • It does not implement OpenAI's own Realtime API.
  • Claude: uses the Claude adapter and @anthropic-ai/sdk.
  • OpenAI chat completions: works with any server that speaks the API, including Ollama and LM Studio.
  • OpenAI Responses: works with OpenAI and Azure OpenAI.
  • Gemini Live: uses Google's Gemini Live API for spoken calls.
  • Azure Voice Live: uses Azure Voice Live through a server relay.
    A reply is HTML that grows, with no message protocol between server and browser. A model's vocabulary is a folder of components, read from each component file. The renderer passes only catalog tags and declared props, then escapes everything else. Approvals, tool results, and failures are stored as parts of a message. A component that talks back is a form, so it works without scripts.
npm install @bascik/ai npx bascik add @bascik/ai

The first command installs the functions, and the second copies the components into your project.
