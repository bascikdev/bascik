HTML components.
Zero runtime.

What if you could have components that were just HTML files without any special syntax? Now you can. Bascik is a build tool for HTML components with automatically scoped CSS and JS. Zero runtime. The code that ships is the code you wrote.

How it works

No imports. No exports. Just use the tag.

Create a file named after your component and add your HTML, CSS, and JavaScript. Then use that tag in any page or component. Bascik finds it automatically, with no import, export, or registration step.

Scoping

One component. Multiple isolated instances.

Bascik scopes CSS class names and DOM selectors at build time. Each instance gets its own namespace with no runtime JS, no Shadow DOM, and no virtual DOM.

Progressive streaming without a client framework

Browsers have parsed chunked HTML since the 90s. When you stream HTML with Bascik, the browser displays the page as it arrives. No React hydration, no virtual DOM diffing, and no client-side fetch polling.

  • Immediate first paint: Static shell and skeleton placeholders flush right away.
  • Zero layout shift: CSS :has() swaps out the skeleton in place when the HTML chunk arrives.
  • Early-paint footer: Send the footer in chunk 1, position it visually with CSS order.

Build Performance

Sub-second build speeds. Zero runtime overhead.

Bascik transpiles and scopes static HTML components in milliseconds with zero runtime overhead. Pure component and style scoping executes in under 0.2ms per page. In real-world projects with heavy build-time execution, Bascik parallelizes and caches builds automatically: across this documentation site's 85 pages executing hundreds of custom Node.js build scripts to render Markdown and extract demo blocks, the entire site transpiles for dev startup in about 1.4 seconds with a warm cache and workers enabled on multi-core hardware.

Warm vs. Cold Startup Note: The ~1.4s dev startup transpile time reflects a warm start with workers enabled on multi-core hardware and SHA-256 build script output caching enabled. On a fresh cold start (or after clearing node_modules/.cache/bascik), Bascik runs each uncached build script in its own isolated child process bounded by a concurrency-aware semaphore, compiling all 85 pages and hundreds of Markdown scripts in ~3.8s on an M1 MacBook Air. Once cached, subsequent restarts and live-reload edits compile in milliseconds.
