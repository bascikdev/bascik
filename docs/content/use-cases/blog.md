# Blog

A Bascik blog is a folder of Markdown files turned into static HTML at build time: posts, a paginated archive, tag pages, and an Atom feed. The finished site is plain HTML and CSS with no client JavaScript, so any static host can serve it.

## Start from the starter

The `blog` starter is a complete blog with sample posts that explain how each feature works. Create a project from it:

```sh
npm create bascik@rc my-blog -- --example blog
cd my-blog
cp .env.example .env
npm run dev
```

Open **http://localhost:8080**. Drafts are visible in development. Replace the sample posts and `content/about.md` with your own.

Create it with a `create-bascik` release that supports `--example` and a compatible Bascik release. It also needs Node.js 24 or later and an internet connection because the starter is downloaded from GitHub. See the [Template Catalog](/use-cases/templates#blog) for the screenshots, source, license, and starter version.

## Page structure

| Address | Page | Template |
| --- | --- | --- |
| `/` | Home: the latest posts | `src/pages/index.html` |
| `/blog/` | Archive, page 1 | `src/pages/blog/index.html` |
| `/blog/page/2/` and up | Archive, later pages | `src/pages/blog/page/[page]/index.html` |
| `/blog/<name>/` | One post | `src/pages/blog/[slug]/index.html` |
| `/tags/` | Every tag | `src/pages/tags/index.html` |
| `/tags/<tag>/` | Posts with one tag | `src/pages/tags/[tag]/index.html` |
| `/about/` | About page, from `content/about.md` | `src/pages/about/index.html` |
| `/404.html` | Page for unknown addresses | `src/pages/404.html` |
| `/feed/feed.xml` | Atom feed | `scripts/generate-feed.ts` |
| `/sitemap.xml`, `/robots.txt` | Generated by Bascik | built in |

The header and footer are the only components. The `<head>` of every page, with its title, canonical link, and link-preview tags, comes from one function, `renderHead()` in `src/lib/render.ts`.

## Content workflow

Each post is a Markdown file in `content/blog/`. The file name becomes the address, so `my-post.md` is published at `/blog/my-post/`. Use lowercase letters, digits, and single hyphens.

```md
---
title: My post
description: One sentence for search results and link previews.
date: 2026-07-01
tags: [notes]
---
Text goes here.
```

`title` and `date` are required. `description`, `tags`, `draft`, `image`, and `imageAlt` are optional. Any other key is an error, so a typo such as `tag:` is caught instead of ignored.

- **Drafts.** Add `draft: true`. A draft appears only in development, marked "(draft)". A production build leaves it out of every page, the sitemap, and the feed, and does not copy its images.
- **Tags.** Each tag gets a page. `Field notes` is published at `/tags/field-notes/`. Two tags that would share an address, such as `Notes` and `notes`, fail the build instead of merging.
- **Links between posts.** Link to another post by its file path, as in `[the welcome post](welcome.md)`. The build rewrites it to the final address. A link to a missing file, or from a published post to a draft, fails the production build.
- **Images.** A post that keeps images beside it lives at `content/blog/name/name.md`. The images are copied to the same path in the output.
- **Responsive images.** Save resized copies beside the original with the width in the name (`harbor.png`, `harbor-960w.png`, `harbor-480w.png`). The build checks each width and shape, then writes a `srcset`. A wrong copy fails the build and names the file. The starter has no image library, so it cannot resize for you.

## How it is built

Bascik has no content collections, so the starter writes its own in ordinary TypeScript:

1. `src/lib/posts.ts` reads `content/blog` with `node:fs`, parses the front matter with `gray-matter`, and validates it with `zod`. It returns the posts in date order.
2. `src/lib/markdown.ts` renders Markdown with `marked` and highlights code with Prism, both at build time.
3. Page templates call these helpers from [build scripts](/build-scripts). Every interpolated value is escaped.
4. Posts, tag pages, and archive pages are [dynamic routes](/dynamic-routes). Each template exports its list of routes from a `data-bascik-routes` script.
5. Two [exec scripts](/exec-scripts) write files that are not pages: one copies post images, and one writes the Atom feed after the pages are built.

Because the pages read `content/`, which Bascik cannot see through imports, `bascik.config.ts` excludes pages and components from the script cache and lists `content/`, `src/lib/`, and `src/data/` in `pipeline.watchPaths` so the development server rebuilds when content changes. See [Build Scripts](/build-scripts) and [Watch Paths](/watch-paths).

## Build and deploy

The finished site is the `dist/` folder.

```sh
BASCIK_SITE_URL=https://blog.example.com npm run build
npm run serve
```

- **Set the site URL.** Canonical links, link previews, the feed, `sitemap.xml`, and `robots.txt` all need the real address. Set `BASCIK_SITE_URL` in `.env`, in your host's build settings, or pass `--site-url`. A production build without one fails. Development does not need it.
- **Serve from the root of a domain.** A site URL with a path, such as `https://user.github.io/repo`, is rejected on purpose, because every internal link is root-relative.
- **Serve `404.html` for unknown addresses.** Most static hosts do this automatically.
- **Upload `dist/` to any static host.** `npm run serve` serves it the way production will, which is the best place to look before uploading. See [Static Hosting](/deployment/static-hosting).

## Customize

| To change | Edit |
| --- | --- |
| Site name, description, language, author | `src/data/site.ts` |
| Header navigation | `NAV` in `src/data/site.ts` |
| Posts per archive page, home page count, feed length | `src/data/site.ts` |
| Colors, fonts, widths | custom properties at the top of `src/css/global.css` |
| Social card and icon | `src/pages/assets/social-card.png` and `favicon.svg` |
| Page layout | `src/pages/` and the components in `src/components/` |
| How Markdown becomes HTML | `src/lib/markdown.ts` and `src/lib/render.ts` |

To add a page, put a Markdown file in `content/` for a simple page or an HTML file in `src/pages/` for a custom one, then add it to `NAV`.

## Integrations

The starter has no comments, analytics, newsletter sign-up, search, or automatic image resizing. Each one needs a decision about a provider, cost, and reader privacy, so none is included. To add one, load its script from `renderHead()` or from a page template, and review what it collects before you ship it.

Search is a good fit for an [exec script](/exec-scripts) that writes an index into the output folder during the build, the same way the starter writes its feed. Automatic image resizing can be a build step that writes the width-named copies the starter already validates.

## Limits and what was not checked

- No hosting provider has been tested. Follow your host's instructions for static sites and point it at `dist/`.
- Browser checks ran in Chromium. Other browsers and screen readers were not tested.
- Heading anchors use CSS anchor positioning. In a browser without it, the `#` link is still reachable but sits after the heading instead of beside it.
- Raw HTML in a post is passed through unchanged. Publish only text you wrote or trust.
- With five or fewer posts, Bascik prints a warning that the archive page template produced 0 routes. That template creates archive pages 2 and up, so there is nothing for it to do yet.
- Dates are formatted in UTC, so a build gives the same result on any machine.
